## R002 — durable recovery and entitlement preflight
- Dev-only native journal: exclusive OS file lock, sequential bounded records, synchronous write before effects, replay of validated state transitions, and recovery of an outstanding claim as Unknown/Reconcile. No automatic re-dispatch. A saved Ready state is historical and requires live revalidation after reopening.
- Journal stores opaque identity references and operation IDs only; assumes a private Host-owned dev directory. It does not itself provision ACLs, authenticate remote observations, guarantee power-loss-safe directory creation, or protect against a malicious local writer. Malformed/truncated journal refuses recovery; do not silently truncate or recreate it.
- Official Secure MCP Tunnel documentation reconfirmed 2026-11-25: tunnel CRUD via official CLI requires an admin key and Tunnels Manage; runtime requires restricted Tunnels Read/Use, and ChatGPT requires linked workspace/custom MCP permission. Browser account sign-in is not entitlement. Use supported locally authorized Platform UI for provisioning; never acquire/store admin keys as runtime credentials. Unknown facts lead to discovery, denied facts to targeted authorization, not an automatic paid upgrade. Transport policy includes required mTLS where applicable.
- Preflight checks independently observed linked workspace, custom MCP, tunnel management, restricted runtime key creation and transport policy. It is pure logic; not an actual entitlement probe.
- Native GPUI will consume this state, with existing Host providing trusted adapters, private directory/credential storage and release isolation. No change to production or actual provisioning.
- Test command: rustc --edition=2021 --test src/lib.rs -o onboarding-tests.exe; ./onboarding-tests.exe. Test coverage includes real filesystem lock/reopen, truncation, account binding, uncommitted claims, verified completion and entitlement decisions.
