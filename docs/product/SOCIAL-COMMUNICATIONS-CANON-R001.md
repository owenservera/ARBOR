# Native Social & Communications Canon — R001

2026-11-25 | Owner directive | Status: mandated; implementation and live acceptance pending.

## Scope
Facebook and WhatsApp are first-class VIVIM ARBOR integrations, present in canonical main and the source-matched local workstation. Extend the existing Studio external-software subsystem, Host authority, Rust semantic/capability registry, GPUI and remote PWA viewport. No separate product renderer, browser actor, permission system or private corpus in Git. Follow STUDIO-CORE-CONVERGENCE-R001.md and existing active source ownership.

## Capability roadmap
1. Inventory existing adapters and lawful, supported interaction surfaces; verify account-specific authorization and site restrictions before implementation. Use the dedicated signed-in browser profile and existing supervised Studio actuator; no credential extraction or unofficial API dependency.
2. Read-only: launch/navigate, identify active account and conversation, inspect user-authorized visible messages and permitted content, search and project scoped metadata into personal World/AutoWiki. Distinguish observed, stale and unknown facts.
3. Typed actions: draft and edit messages, attach user-selected files, navigate Facebook content, prepare posts and replies. All sends, posts, reactions, deletes and other external effects require exact target, current account, explicit Host authorization and readback/receipt; uncertain effects must not be retried automatically.
4. Register grounded capabilities and deterministic VLANG intents, expose them in GPUI and its authenticated PWA viewport, retain one authority and one browser actuator. Rust first for pure computational logic; reuse working browser transport.
5. Local and main acceptance: source-pinned build, adapter-specific observation tests, authorized live read/draft, separately approved send/post if applicable, receipt/readback, phone parity, drift invalidation, rollback and privacy checks. Respect platform restrictions; unsupported actions remain explicitly unavailable.

## Delivery
Reconcile active Studio/Core-IP claims before code changes. Product source goes on ARBOR main; local deployment must match reviewed source. Document implementation and actual acceptance separately; this directive alone is not runtime evidence. Do not store personal messages, authentication data or session material in source control.
