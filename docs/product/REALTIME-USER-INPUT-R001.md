# Real-time user input — native primitive R001
Owner direction 2026-11-25: the simplest usable VIVIM instance is the actual user textbox and always-live AutoWiki/command intelligence. Thousand-agent research campaigns include agents acting as users typing into real product instances, not just agents editing source. 
Existing source: GPUI main on_composer_changed/read_composer_semantics uses edit epochs, 280ms debounce, one in-flight read and latest retry; existing Wiki search reads admitted Host Wiki immediately and refreshes with 2s bound; first_contact.rs preserves independent 160-char Wiki vs 1000 UTF16-unit interpretation limit. Host intent-planner and command-intent share VEC/NLCL, canonical action catalog and personal rules. composerResponse binds exact input, action, risk, readiness, slots and revision metadata. agent_composer.rs and Host bridge currently stage a single selected phone composer with owner authority, bounded eight cached observations; NOT a thousand-agent runner. live_system.rs already supplies typed region revision fences. Reuse, not another grammar/renderer/store.
Implemented: move the existing GPUI inert command projection into shared Rust core realtime_command.rs; expose registration, catalog readiness (executor wired vs live verified), available revision metadata, explicit no execution/authorization. Require exact current draft on real client response; preserve existing validation and risk-aware argument redaction. GPUI uses shared projection and shows the distinct layers. Diagnostic native example accepts actual Host responses for testing. Native UI build/live acceptance still requires evidence.
Next: compose special live-user-context class with two independently versioned projections: realtime Wiki (current relevant authorized pages, explanation of capability, related knowledge, no inferred facts as verified), realtime command (draft, interpretation/ambiguity/missing slots, typed candidate, registered capability/contract, source-wired/live-verified readiness, actual eligibility and separate Host plan/receipt). Empty input shows neutral ready/unknown state; do not reveal private pages by default. Preserve existing live typing rules and one GPUI renderer. Draft is not command execution. Typing never changes Wiki or sends external effects; explicit submit/review/Host execution is distinct. Unknown registration and unsupported intent are not the same. Candidate registration alone cannot prove present eligibility. Distinguish draft revision, catalog/world revision, Wiki revision, graph/lens/policy revisions and exact plan/receipt. 
Real user test interface: use isolated product instances with real GPUI composer and actual accepted input event reducer; authenticated per-instance agent actor has only user-equivalent access to that instance, no development tools or prod credentials. Agent types partial utterance, observes actual rendered/readable projection, revises/clarifies, optionally submits and uses only authorized test-instance actions; collect actual outcome and latency, no source edit. Headless diagnostic probes reuse compiler for cheap broad regression but are not GUI acceptance. Start one real instance then two isolated users; scale logical campaign to 1000 with bounded active resources. Existing phone bridge single selected region cannot be reused unchanged for concurrent agents. Need instance-scoped transport, input/event ack, exact draft/source revisions, coalescing, cancellation and no cross-instance leakage; avoid new scheduler. Track intent accuracy, clarification rate, catalog mismatches, stale previews, Wiki relevance, time to useful result, task success and unintended effects. Human user acceptance separate. 
Release one: actual native input -> real-time command and Wiki -> revision-bound observation -> explicit submit -> actual receipt/readback -> telemetry and independent evaluation; no direct developer API counted as user testing. This is an initial implementation seam, not deployed full user testing system.

## Shared dual projection
The same core now exports project_wiki (delegates to incumbent bounded Wiki search) and project_user_context, an inert live-user-context/1 bundle with independently stamped Wiki and command readings, explicit revision relationship and draft revision. Native GPUI uses the shared Wiki projection and command reading; neutral always-present Wiki status reveals no private content before typing. Headless example reads actual Host response envelopes. The bundle is not a Host grant or proof of cross-source atomicity, and no actual GPUI instance agent interface has been deployed. Native input producer and projection consumers still need explicit session/instance binding and actual rendered readback.
